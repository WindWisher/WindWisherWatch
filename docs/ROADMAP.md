# Technical roadmap

The Session Engine—not the Jump Engine—is the wearable core. Milestones advance only when acceptance evidence exists; simulator success cannot establish hardware sensor quality, battery budget, or production accuracy.

| Milestone                           | Objective and deliverables                                                                         | Acceptance criteria                                                                      | Explicit non-goals                                  | Dependencies and key risks                         |
| ----------------------------------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------- | -------------------------------------------------- |
| M0 Foundation — DONE                | Product/domain specs, ADRs, schemas, fixtures, validators, CI                                      | Foundation checks and review gates                                                       | Runtime, sensors, algorithms, sync                  | Versioned semantics established                    |
| M1 Garmin Sensor Lab — DONE         | Device App harness and host tooling for GPS/IMU/barometer/HR, clocks, storage, runtime and battery | Reproducible simulator and representative-hardware evidence with device/firmware/profile | Session Engine, jump detection, FIT, product UI     | Residual gyro quality risk deferred to M4 research |
| M2 Session Engine Foundation — DONE | Canonical lifecycle, primary recording, bounded durable journal, recovery and essential live state | Partial-tail/checksum recovery, bounds, Garmin builds and representative hardware smoke  | Jump detection, advanced analytics, production sync | Power-loss atomicity remains unknown               |
| M3 Core Session Metrics             | Only required live time, HR, current/max speed and distance projections                            | Defined accuracy/resource behavior and raw-data preservation                             | Historical/P95/VMG/jibe/scores                      | M2 trustworthy streams                             |
| M4 Jump Engine Experimental         | Isolated replayable candidate/event pipeline                                                       | Versioned algorithm and explicit insufficient-evidence behavior                          | Production claims and UI coupling                   | M1/M2 telemetry and labels                         |
| M5 Jump Metrics + Woo Validation    | Height/airtime/distance estimates and consented comparison framework                               | Predeclared detection/error KPIs by capability cohort                                    | Treating Woo as ground truth                        | M4, consent, clock alignment                       |
| M6 Garmin Session UX                | Native glanceable Jump/Ride experience and offline forecast snapshot                               | Wet-use/device tests, missing-quality states, measured battery                           | Social, maps, live wind estimation                  | M2-M5                                              |
| M7 Session Sync Protocol            | Vendor-neutral packaging, retry, acknowledgement and conflict handling                             | Duplicate/reorder/partial/replay/security tests                                          | Independent backend                                 | Stable session dataset and auth design             |
| M8 WindWisher Integration           | Backend ingestion and Flutter analytics/history consumption                                        | Private end-to-end sync, RLS/auth, migration and rollback                                | Public-by-default sharing                           | M7 and main-app coordination                       |
| M9 Garmin Production Hardening      | Reliability, privacy, performance and release readiness                                            | Device coverage, soak, battery, storage, security and recovery gates                     | New platforms                                       | Representative hardware/store policy               |
| M10 watchOS                         | Native Swift/SwiftUI vertical slice using shared semantics                                         | Hardware evidence and capability-based parity                                            | Shared runtime                                      | M9 learnings and Apple constraints                 |
| M11 Wear OS                         | Native Kotlin/Compose vertical slice using shared semantics                                        | Hardware evidence and capability-based parity                                            | Shared runtime                                      | M9/M10 learnings and device fragmentation          |
