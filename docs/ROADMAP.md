# Technical roadmap

Each milestone requires its own evidence and must preserve privacy, offline recording, explicit units, and versioned provenance.

| Milestone                      | Objective and deliverables                                                                                   | Acceptance criteria                                                               | Explicit non-goals                      | Dependencies and key risks                                |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- | --------------------------------------- | --------------------------------------------------------- |
| M0 Foundation                  | Product/domain specs, ADRs, schemas, fixtures, validators, CI                                                | `npm run check`; review gates pass; no runtime                                    | Sensors, apps, algorithms, sync         | Risk: premature semantics; mitigated by versioning        |
| M1 Garmin Sensor Lab           | Minimal research harnesses and device matrix for timestamps, GPS/IMU/HR/barometer, storage, runtime, battery | Reproducible on-device measurements with model/firmware/profile; raw exports      | Session product, jump detection         | Garmin hardware/toolchain; sensor and battery variability |
| M2 Raw Session Recorder        | Crash-safe offline Garmin recording and export                                                               | Power/crash recovery, bounded storage, integrity and battery evidence             | Jump metrics, production sync           | M1 profiles; storage constraints                          |
| M3 Jump Engine v0 Experimental | Offline analysis pipeline and candidate detector                                                             | Versioned algorithm, replayable datasets, explicit insufficient-evidence behavior | Product accuracy claims                 | M2 telemetry; labeling quality                            |
| M4 Jump Metrics v1             | Height/airtime/distance estimators for supported profiles                                                    | Predeclared error evaluation and confidence/quality behavior                      | Unsupported-device equivalence          | M3, calibration reference; model bias                     |
| M5 Woo Validation Framework    | Reproducible, consented comparison pipeline                                                                  | One-to-one matching and reported precision/recall/error by cohort                 | Calling Woo ground truth; mandatory API | M4, rights/consent, clock alignment                       |
| M6 Garmin UX v1                | Native glanceable Jump/Ride/Forecast experience                                                              | Wet-use/device tests, missing-quality states, measured battery                    | Social, maps, live wind estimation      | M2-M5; display/input diversity                            |
| M7 WindWisher Sync Protocol    | Implement transport-neutral packaging, retries, acknowledgements                                             | Duplicate/reorder/partial/replay tests; threat review                             | UI integration, independent backend     | Stable contracts; auth and quotas                         |
| M8 WindWisher Integration      | Backend ingestion and Flutter session consumption                                                            | RLS/auth, migrations, end-to-end private sync, rollback                           | Public-by-default sharing               | M7 and WindWisher coordination                            |
| M9 Garmin Production Hardening | Reliability, performance, privacy, release readiness                                                         | Device coverage, soak/battery/storage/security/recovery gates                     | New platforms                           | Representative hardware; store policy                     |
| M10 watchOS                    | Native Swift/SwiftUI vertical slice using shared semantics                                                   | Hardware evidence and parity defined by capability, not identical UI              | Shared runtime                          | M9 learnings; Apple APIs/policies                         |
| M11 Wear OS                    | Native Kotlin/Compose vertical slice using shared semantics                                                  | Hardware evidence and capability-based parity                                     | Shared runtime                          | M9/M10 learnings; device fragmentation                    |

Milestones advance only when acceptance evidence exists. In particular, synthetic or simulator success cannot establish device sensor quality, battery budget, or production jump accuracy.
